# 总结

在这个实验中，你学习了如何在 GitHub Actions 中编排多任务工作流。你：

1. 创建了独立的 `build` 和 `deploy` 任务。
2. 使用了 `needs` 关键字来定义依赖关系，确保 `deploy` 仅在 `build` 之后运行。
3. 使用了 `upload-artifact` 和 `download-artifact` 在这些独立任务之间传递数据（文件）。

这种模式对于构建健壮的 CI/CD 流水线至关重要，在这种流水线中，你希望只构建一次，并且只有在先前步骤成功的情况下才部署到多个环境（预演环境 staging、生产环境 production）。
