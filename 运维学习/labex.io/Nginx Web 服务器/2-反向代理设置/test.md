# 简介

在本实验中，你将学习如何配置 Nginx 作为**反向代理**（Reverse Proxy）。

可以将反向代理想象成大公司的前台接待员。当你拨打总机号码时，你不会直接与首席执行官或支持团队通话。你会先与前台接待员沟通，对方会询问「有什么可以帮你的？」，然后将你的电话转接到相关人员。

在这个场景中：

- **Nginx** 是前台接待员（监听 80 端口）。
- **Python 应用** 是「支持团队」（监听 8000 端口）。
- **你** 是拨打电话的客户端。

你将设置 Nginx，使得当有人请求 `/app` 时，Nginx 会将该请求转发给 Python 服务器，并将响应返回给客户端。

反向代理是现代 Web 架构的核心。它们位于应用程序服务器之前，提供稳定的公共入口点，并可以处理 TLS 终止、负载均衡、缓存和请求路由。

这意味着 Nginx 并不总是直接提供文件服务。有时它的主要工作是接收客户端流量，并将这些流量传递给其背后的其他服务。
# 启动后端应用程序

首先，我们需要一个可以「代理」请求的目标。我们将使用 Python 创建一个非常简单的 Web 应用程序。

我们将为应用程序创建一个专门的文件夹来存放文件。

在你的项目目录中创建一个名为 `app` 的文件夹，并在其中创建一个简单的 HTML 文件：

```bash
mkdir -p ~/project/app
echo "Hello from the Python Backend." > ~/project/app/index.html
```

现在，让我们启动 Python 服务器。此命令告诉 Python 作为 Web 服务器运行，从当前目录提供文件，端口为 **8000**。

这个 Python 进程就是我们示例中的**后端应用程序服务器**。它将处理实际的内容生成，而 Nginx 将作为面向公众的入口点位于其前端。

我们在末尾添加 `&` 符号，以便在**后台**运行它。这样你可以在服务器静默运行的同时继续使用终端。

```bash
cd ~/project
python3 -m http.server 8000 &
```

让我们验证它是否已正确启动。我们查找监听 8000 端口的进程：

```bash
netstat -tuln | grep 8000
```

你应该看到输出显示 `0.0.0.0:8000` (LISTEN)。这意味着我们的「后端应用」已准备好在 8000 端口接收请求。
# 配置 Nginx 反向代理

在这一步中，你将修改 Nginx 配置文件，告知它关于我们 Python 应用的信息。

我们需要使用 `sudo` 和 `nano` 文本编辑器来编辑默认配置文件。

```bash
sudo nano /etc/nginx/sites-enabled/default
```

在 `server { ... }` 块中向下滚动。你会看到一个现有的 `location / { ... }` 块。我们需要在它下方添加一个新的 `location /app` 块。

将以下代码添加到文件中（注意花括号 `{ }` 和分号 `;`）：

```nginx
    location /app {
        proxy_pass http://127.0.0.1:8000;
    }
```

**这段代码的作用是什么？**

- `location /app`：告诉 Nginx 监听以 `/app` 开头的请求。
- `proxy_pass ...`：充当呼叫转接按钮。它告诉 Nginx：「当你收到对 `/app` 的请求时，将其转发到端口 8000 上的 `localhost` (127.0.0.1)。」

这种转发正是反向代理的精髓。客户端与 Nginx 对话，但 Nginx 代表用户成为了后端服务器的客户端。

你的文件结构应该类似于这样：

```nginx
server {
    listen 80 default_server;
    ...
    location / {
        try_files $uri $uri/ =404;
    }

    location /app {
        proxy_pass http://127.0.0.1:8000;
    }
}
```

按 `Ctrl+O` 然后按 `Enter` 保存文件，按 `Ctrl+X` 退出 `nano`。
# 验证并重载

我们已经更新了配置文件，但 Nginx 仍在运行旧规则。我们需要重载该服务。

首先，在重载之前**务必**检查配置是否有拼写错误。如果你重载了一个错误的配置，Web 服务器可能会完全停止工作。

运行测试命令：

```bash
sudo nginx -t
```

你应该看到：`syntax is ok`
`test is successful`

如果测试通过，重载 Nginx 以应用更改：

```bash
sudo service nginx reload
```

Nginx 现在已经更新了指令，并准备好转发请求了。

此时，Nginx 充当的是 URL 和后端服务之间的路由器，而不仅仅是一个从磁盘读取文件的文件服务器。
# 测试代理

在最后一步中，我们将验证我们的「接待员」是否在正常工作。

我们将向 Nginx (80 端口) 发送一个 Web 请求，请求 `/app/`。Nginx 应该立即将其转发给 Python 服务器 (8000 端口)。

运行以下命令：

```bash
curl http://localhost/app/
```

你应该看到来自我们后端服务器的消息：

```plaintext
Hello from the Python Backend.
```

**刚才发生了什么？**

1. **你** 向 Nginx (`localhost:80`) 请求 `/app/`。
2. **Nginx** 检查其规则，匹配到 `/app`，并遵循 `proxy_pass` 指令。
3. **Nginx** 调用了端口 8000 上的 **Python 服务器**。
4. **Python 服务器** 将「Hello...」页面返回给 Nginx。
5. **Nginx** 将「Hello...」页面返回给 **你**。

这个请求链非常值得记住，因为它在现代基础设施中随处可见：浏览器 -> 反向代理 -> 应用程序服务器 -> 反向代理 -> 浏览器。

你已经成功构建了一个反向代理！
# 总结

在本实验中，你已成功配置 Nginx 作为反向代理。你学习了如何：

1. **托管**：使用 Python 托管一个简单的后端应用程序。
2. **配置**：使用 `location` 块配置 Nginx 进行路由。
3. **转发**：使用 `proxy_pass` 指令转发流量。
4. **验证**：使用 `curl` 验证代理链。

这种架构是现代 Web 应用程序的骨干，它允许你利用 Nginx 进行安全防护和负载均衡，同时让其他应用程序在后台处理业务逻辑。
