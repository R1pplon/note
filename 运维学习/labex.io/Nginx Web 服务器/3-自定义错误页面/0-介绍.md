# 简介

你是否曾点击过一个失效链接，然后跳转到一个平淡无奇、甚至有些简陋的页面，上面只写着「404 Not Found」？这种体验既令人沮丧，也毫无帮助。

在本实验中，你将学习如何通过创建**自定义错误页面**来改善这一状况。

HTTP 错误代码（如 `404`）是 Web 标准响应语言的一部分。`404 Not Found` 响应意味着服务器可以访问，但请求的资源在该路径下不存在。

这种区分非常重要。404 并不代表服务器崩溃，它意味着服务器成功处理了请求，并明确告知该资源未找到。

可以将标准的 404 页面想象成一个写着「死胡同」的通用路标。而*自定义*的 404 页面则像是一个礼貌且带有品牌特色的指示牌，上面写着：「抱歉，此路不通，但这里有一张地图可以帮你回到正轨。」

你将完成以下任务：

1. 设计你自己的「页面未找到」提示页（HTML 文件）。
2. 配置 Nginx，使其在用户迷路时自动显示该页面。
3. 进行测试，确保它能提供更好的用户体验。
