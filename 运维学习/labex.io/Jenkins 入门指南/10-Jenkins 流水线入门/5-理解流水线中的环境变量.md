# 理解流水线中的环境变量

在最后一步中，你将学习环境变量。`environment` 指令允许你定义可在整个流水线中使用的变量，这非常适合在不将配置硬编码到步骤中的情况下管理配置设置。

本地仓库中的 `Jenkinsfile` 已经通过一个指定部署目标的环境变量演示了这个概念。

让我们检查一下环境变量是如何定义和使用的：

```groovy
pipeline {
    agent any
    environment {
        DEPLOY_TARGET = 'staging'
    }
    stages {
        // ... 其他阶段 ...
        stage('Deploy') {
            steps {
                echo "Deploying the application to ${env.DEPLOY_TARGET}..."
                sh 'echo "Application deployed successfully!"'
            }
        }
    }
}
```

关于 Jenkins 流水线中环境变量的关键点：

- `environment { ... }` 块定义了在整个流水线中可用的变量。
- 变量使用 `${env.VARIABLE_NAME}` 语法进行访问。
- 对于包含变量插值的字符串，务必使用双引号 (`"`)，因为 Groovy 的变量插值仅在双引号字符串中有效。
- 环境变量使你的流水线更加灵活且易于维护。

1. 如果尚未操作，请通过点击 **Build Now** 在 Jenkins 中触发一次新的构建。

2. 构建完成后，检查该构建的 **Console Output**。在 "Deploy" 阶段的日志中，你将看到变量已被正确替换：

```plaintext
...
[Pipeline] { (Deploy)
[Pipeline] echo
Deploying the application to staging...
[Pipeline] sh
+ echo Application deployed successfully!
Application deployed successfully!
[Pipeline] } // stage
...
Finished: SUCCESS
```

3. 注意 `DEPLOY_TARGET` 环境变量的值 `staging` 是如何自动替换到 echo 语句中的。

环境变量对于创建灵活的流水线至关重要，这些流水线可以轻松配置用于不同的环境（开发、测试、生产），而无需修改流水线代码本身。
