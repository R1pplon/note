### 一、 脚本声明与执行
1. **Shebang**：`#!/bin/bash` 
2. **执行方式**：
   * 赋权执行：`chmod +x script.sh` -> `./script.sh`（开启子进程执行）
   * 解释器执行：`bash script.sh`（开启子进程执行）
   * 当前环境执行：`source script.sh` 或 `. script.sh`（常用于加载配置/环境变量，不开启子进程）
### 二、 变量与赋值
Bash 默认一切皆字符串。
1. **赋值规则**：`VAR=value`
   * **等号两侧绝对不能有空格**（有空格会被解析为命令和参数）。
   * 值中如有空格，必须用引号包裹：`VAR="hello world"`
2. **取值规则**：`$VAR` 或 `${VAR}`
   * 大括号用于界定变量名边界：`echo "${VAR}_suffix"`
3. **变量分类**：
   * 局部变量：仅当前进程可见。
   * 环境变量：`export VAR=value`，子进程可见。
   * 只读变量：`readonly VAR`，不可修改/删除。
4. **特殊只读变量**：
   * `$?`：上一条命令的退出状态码（0为成功，非0为失败）
   * `$$`：当前脚本的 PID。
   * `$!`：最近一次放入后台执行的进程 PID。
### 三、 位置参数（脚本/函数的传参）
不使用括号传参，而是通过内置变量接收。
1. `$0`：脚本文件名本身。
2. `$1` 到 `$9`：第1到第9个参数。
3. `${10}`：第10个及以上的参数，必须加括号。
4. `$#`：参数的总个数。
5. `$@`：所有参数（作为独立字符串，常用于循环遍历）。
6. `$*`：所有参数（作为一个整体字符串）。
### 四、 引号与转义
这是 Bash 解析机制的核心，决定了字符的“字面量”与“替换”行为。
1. **反斜杠 `\`**：转义单个字符，恢复其字面量（如 `\$` 打印出 `$`）。
2. **单引号 `''`**：**硬引号**，绝对字面量，内部所有特殊字符（包括 `$`、`\`）全部失去特殊含义，原样输出。
3. **双引号 `""`**：**软引号**，保留部分特殊含义。内部允许变量替换（`$`）、命令替换（`` ` ` `` / `$()`）和转义（`\`），其余字符原样输出。**常用于包裹含空格的变量，防止分词。**
### 五、 命令替换与算术运算
1. **命令替换**：将命令的输出结果赋值给变量。
   * 推荐写法：`VAL=$(command arg)` 
   * 旧写法：`` VAL=`command arg` ``（不推荐，嵌套困难）
2. **算术运算**：Bash 原生只支持整数运算。
   * 推荐写法：`$(( expression ))`，例如 `RESULT=$(( 5 + 3 ))`
   * 内部变量无需加 `$`：`$(( a + b ))` 等同于 `$(( $a + $b ))`
   * 支持运算：`+`, `-`, `*`, `/`（整除）, `%`（取余）, `**`（求幂）
   * 支持自增/自减：`(( i++ ))`, `(( i-- ))`, `(( i += 2 ))`
### 六、 字符串操作
Bash 处理字符串能力极强，全靠 `${...}` 语法。
1. **获取长度**：`${#VAR}`
2. **提取子串**：`${VAR:offset:length}`（从 offset 开始，取 length 个字符，索引从0开始）
3. **默认值**：
   * `${VAR:-default}`：如果 VAR 未设置或为空，返回 default，但不改变 VAR 的值。
   * `${VAR:=default}`：如果 VAR 未设置或为空，将 VAR 赋值为 default 并返回。
4. **替换**：
   * `${VAR/pattern/replacement}`：替换第一个匹配。
   * `${VAR//pattern/replacement}`：替换所有匹配。
5. **删除（常用于处理文件路径后缀）**：
   * `${VAR#pattern}`：从头部删除最短匹配。
   * `${VAR##pattern}`：从头部删除最长匹配。
   * `${VAR%pattern}`：从尾部删除最短匹配。
   * `${VAR%%pattern}`：从尾部删除最长匹配。
### 七、 条件判断与分支
1. **测试原语**：
   * `[ condition ]`：POSIX 标准测试，注意括号两侧必须有空格。
   * `[[ condition ]]`：**Bash 增强测试，推荐使用**。支持正则匹配 `=~`，支持逻辑运算符 `&&` 和 `||`，且对空格和引号的容错率更高。
2. **常用测试条件**：
   * 文件判断：`-f` (存在且为文件), `-d` (目录), `-e` (存在), `-r` (可读), `-x` (可执行)
   * 字符串判断：`-z` (长度为0), `-n` (长度不为0), `==` (相等), `!=` (不等)
   * 数值判断：`-eq` (等于), `-ne` (不等于), `-gt` (大于), `-lt` (小于), `-ge`, `-le`
3. **if 分支**：
   ```bash
   if [[ condition ]]; then
       commands
   elif [[ condition ]]; then
       commands
   else
       commands
   fi
   ```
4. **case 分支**（常用于菜单/参数解析，支持通配符）：
   ```bash
   case "$VAR" in
       pattern1)
           commands
           ;;
       pattern2|pattern3)
           commands
           ;;
       *)
           commands  # 默认分支
           ;;
   esac
   ```
### 八、 循环
1. **for 循环**：
   * 遍历列表：`for item in list; do commands; done`
   * C语言风格（常用于计数）：`for (( i=0; i<10; i++ )); do commands; done`
2. **while 循环**（条件为真时执行）：
   ```bash
   while [[ condition ]]; do
       commands
   done
   ```
3. **until 循环**（条件为假时执行，较少用）：
   ```bash
   until [[ condition ]]; do
       commands
   done
   ```
4. **循环控制**：`break`（跳出），`continue`（跳过当次）
### 九、 数组
Bash 只支持一维数组，索引从 0 开始。
1. **定义**：
   * 索引数组：`ARR=(val1 val2 val3)`
   * 关联数组（字典，需提前声明）：`declare -A MAP; MAP=([key1]=val1 [key2]=val2)`
2. **取值**：
   * 单个元素：`${ARR[index]}`
   * 所有元素：`${ARR[@]}`（常用） 或 `${ARR[*]}`
3. **获取信息**：
   * 数组长度：`${#ARR[@]}`
   * 所有索引（键）：`${!ARR[@]}`
### 十、 函数
1. **定义**：
   ```bash
   function func_name() {
       commands
   }
   # 或
   func_name() {
       commands
   }
   ```
2. **参数与返回值**：
   * 函数内部通过 `$1`, `$2`, `$@` 接收参数，与脚本接收参数机制完全一致。
   * **函数没有返回字符串的机制**。`return` 只能返回 0-255 的整数（表示执行状态）。
   * 返回字符串的标准做法：函数内部 `echo` 输出，外部用命令替换捕获 `result=$(func_name)`。
3. **变量作用域**：
   * 默认函数内的变量是全局的（会污染外部）。
   * 必须使用 `local VAR=value` 声明函数内的局部变量。
### 十一、 逻辑组合与子进程
1. **逻辑组合**：
   * `cmd1 && cmd2`：cmd1 成功（退出码为0）才执行 cmd2。
   * `cmd1 || cmd2`：cmd1 失败（退出码非0）才执行 cmd2。
2. **子进程执行**：
   * `( commands )`：括号内的命令在一个全新的子 Shell 中执行，内部的变量修改、目录切换（`cd`）完全不影响当前父 Shell。
3. **进程替换**（进阶，但很有用）：
   * `<(cmd)`：将 cmd 的输出视为一个临时文件描述符，传给另一个命令。
---
这就是 Bash 的骨架。你可以按照这个顺序，逐个模块敲代码验证。建议先从“变量与引号”和“条件测试”这两个最容易踩坑的地方开始。
